## Migration guidance

- **Per clone (operators/contributors):** run `git config core.hooksPath .githooks` once to enable
  the commit-message lint (see CONTRIBUTING.md). Optionally run `git gc` to repack loose objects.
- **Whitepaper builds:** keep building to `main.pdf` as before; copy/rename to the project's
  `*_Whitepaper.pdf` to publish. `main.pdf` is now ignored and must not be re-tracked.
- Repo-local `user.email`/`user.name` and `core.hooksPath` are per-clone settings — other clones
  set them manually; `.mailmap` ships in the repo and needs no action.

## Rollback

- Re-track a PDF: delete its two ignore lines and `git add <dir>/latex/main.pdf` (files were never
  deleted from disk).
- Disable the hook: `git config --unset core.hooksPath`; remove `.githooks/` and the
  CONTRIBUTING.md line.
- Identity: delete `.mailmap`; `git config --unset user.email && git config --unset user.name`
  (repo-local only — global config untouched).
- Branches: `git branch feat/pqhash-v1 ef4585f && git branch feat/pqid-hardening-phase-1-3 474a447`.
- Empty dirs: `mkdir -p` recreates them (git never tracked them).
- `git gc` is not reversible and does not need to be — it changes no reachable history.

## Security considerations

None of the security invariants are touched. The commit-msg hook and lockfile/vector freeze checks
are process guards only; `.env` ignoring reduces the chance of committing local secrets.
