\section{The Three Projects}
\label{sec:three-projects}

Each project under \tessera{} is independent on the wire: a consumer can adopt one without adopting any other, and a downstream system that cares about only identifiers (\tesseraid{}) need not pull in SHAKE-256 (\tesserahash{}) or ML-KEM-1024 (\tesseraseal{}). The projects share discipline (Section~\ref{sec:polyglot}), tooling (Section~\ref{sec:conformance}), and a few load-bearing infrastructure pieces (Section~\ref{sec:shared-namespace}), but their wire formats commit to nothing about each other beyond non-collision of variant bytes.

\subsection{\tesseraid{}: post-quantum-era identifier}

\textbf{Project root:} \texttt{tessera-id/}. \textbf{Whitepaper:} \texttt{tessera-id/latex/TesseraID\_Whitepaper.pdf}.

\tesseraid{} is a 41-byte, lexicographically-sortable identifier. Layout: \code{TS(6) || VARIANT(1) || COUNTER(2) || RANDOM(32)}, big-endian. The 32-byte random tail is the security claim: $2^{128}$ second-preimage even against an attacker running Grover's algorithm \citep{grover1996} --- the same security target NIST uses for ML-KEM-1024 \citep{fips203} (which \tesseraseal{} uses; see below). The 16-bit per-millisecond counter and 48-bit timestamp make the format sortable and traceable without coordination.

\tesseraid{} v1 ships two variants:
\begin{itemize}
\item \code{0x01} (Standard): wall-clock-driven. Not internally locked; one generator per thread, or caller-locks.
\item \code{0x02} (HLC): Hybrid Logical Clock \citep{kulkarni2014hlc}. Internally locked. 60-second drift bound: a peer HLC \emph{strictly} more than 60\,000 ms ahead of local physical time is a hard error, never clamped. The bound is normative; an implementation MAY expose a stricter-only local override (smaller than 60\,000 ms) and MUST reject any attempt to configure a larger one.
\end{itemize}

Canonical text encodings: 55-character Base64URL \citep{rfc4648} (no padding) and 66-character Crockford Base32 \citep{crockford} (case-insensitive on decode, \code{I/L $\to$ 1} and \code{O $\to$ 0} confusables accepted). Both round-trip byte-identical with the binary. Crockford ASCII sort preserves generation-time order.

\subsection{\tesserahash{}: SHAKE-256 content hash}

\textbf{Project root:} \texttt{tessera-hash/}. \textbf{Whitepaper:} \texttt{tessera-hash/latex/TesseraHash\_Whitepaper.pdf}.

\tesserahash{} is a 73-byte content identifier. Layout: \code{TS(6) || VARIANT(1) || COUNTER(2) || TAIL(64)}, big-endian. The 64-byte tail is \code{SHAKE-256(content, 64 bytes)} \citep{fips202}; the 9-byte header is layout-identical to \tesseraid{}'s header. The security argument is the SHAKE-256 collision-resistance assumption: $2^{256}$ classical collision, $\sim 2^{170}$ Brassard--H{\o}yer--Tapp \citep{bht1998} quantum collision, $2^{256}$ Grover second-preimage.

\tesserahash{} v1 ships one variant: \code{0x03}. Canonical text encodings: 98-character Base64URL and 117-character Crockford Base32. \tesserahash{} is keyless; it provides no authentication, no confidentiality, and no producer non-repudiation (its threat model is closely tied to ``the SHAKE-256 sponge is what NIST says it is''). Two callers hashing the same content produce identifiers that share the 64-byte tail and differ only in the 9-byte header.

\subsection{\tesseraseal{}: ML-KEM-1024 encryption envelope}

\textbf{Project root:} \texttt{tessera-seal/}. \textbf{Whitepaper:} \texttt{tessera-seal/latex/TesseraSeal\_Whitepaper.pdf}.

\tesseraseal{} is a 16-byte-header variable-body encryption envelope. Header layout: \code{TS(6) || VARIANT(1) || SUITE(1) || COUNTER(2) || KEM\_CT\_LEN(2) || AD\_LEN(4)}; body: \code{KEM\_CT || AD || NONCE(12) || AEAD\_CT || AEAD\_TAG(16) || COMMIT(32)}. The first 9 bytes are layout-compatible with \tesseraid{}'s and \tesserahash{}'s headers; bytes 9--15 are TesseraSeal-specific.

\tesseraseal{} v1.x ships three suites:
\begin{itemize}
\item \code{0x01} (mandatory, pure PQ): ML-KEM-1024 + AES-256-GCM + 32-byte UtC commitment tag \citep{bellare2022commitment} + HKDF-SHA3-256.
\item \code{0x02} (optional, pure PQ): ML-KEM-1024 + ChaCha20-Poly1305 + UtC + HKDF-SHA3-256. For software-only callers without AES hardware.
\item \code{0x06} (optional, hybrid; v1.2, PQCK-00021): X25519 \citep{rfc7748} + ML-KEM-1024 + AES-256-GCM + UtC + HKDF-SHA3-256. Opt-in defense-in-depth; uses an X-Wing--style \citep{xwing-draft} SHAKE-256 combiner over both shared secrets.
\end{itemize}

The suites \code{0x01}/\code{0x02} carry an unambiguous pure-PQ confidentiality promise: residual risk (a structural break of Module-LWE) is accepted in exchange. Suite \code{0x06} is the opt-in alternative that adds a classical safety net via X25519. The wire byte at header offset 7 records which promise the envelope makes; a single envelope never makes both.

\subsection{Common infrastructure}

\textbf{Project root:} \texttt{common/}. Not a normative wire format; a shared library directory whose contents are used by more than one project.

\begin{itemize}
\item \texttt{common/c/keccak.\{h,c\}} (and \texttt{common/java/com/tessera/common/Keccak.java}): SHAKE-256/Keccak. Used by \tesserahash{} (tail computation) and \tesseraseal{} (HKDF salt derivation; hybrid suite combiner). Python and Go use stdlib (\texttt{hashlib.shake\_256}, \texttt{golang.org/x/crypto/sha3}); Rust and TypeScript follow each project's pinned per-language sources (audited crates, or runtime-provided OpenSSL-backed primitives --- see the per-project pin tables). The \texttt{common/} copy is the source of truth for C, C++, and Java.
\item \texttt{common/c/tessera\_header.h}: shared offset constants for the 9-byte header layout (\code{TS}, \code{VARIANT}, \code{COUNTER}). Included by \tesseraseal{}'s C port today; the \tesseraid{} and \tesserahash{} C ports define the same offsets locally (deliberate duplication, per the \texttt{common/} policy below). The first-nine-byte layout itself is identical across all three projects, and the conformance harness keeps it that way.
\item \texttt{common/c/random.\{h,c\}}: OS CSPRNG wrapper. Used by \tesseraid{} (random tail) and \tesseraseal{} (ML-KEM \texttt{Encaps} randomness, X25519 ephemeral keygen).
\item \texttt{common/c/hkdf\_sha3.\{h,c\}}: HMAC-SHA3-256 and HKDF-SHA3-256. \tesseraseal{}-only as of v1.3, vendored alongside the Keccak source.
\end{itemize}

The discipline: code lives under \texttt{common/} only if more than one project depends on it today. The Keccak source moved to \texttt{common/} when \tesseraseal{} became its second consumer (\tesserahash{} alone could vendor it inside the project). The HKDF-SHA3 wrapper has not moved out of \texttt{common/}-\tesseraseal{}-territory because no other project uses it.
