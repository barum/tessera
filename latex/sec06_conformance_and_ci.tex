\section{Conformance and CI}
\label{sec:conformance}

\subsection{The hybrid suite \texorpdfstring{\code{0x06}}{0x06} skip discipline}

\tesseraseal{}'s hybrid suite \code{0x06} (PQCK-00021, v1.2) is a polyglot KAT contract carried by the four languages with their own \tesseraseal{} conformance runners --- Python, C (TSEAL-00030, 2026-06-13), Go, and Rust --- which decrypt the \texttt{hybrid\_*.json} vectors byte-identically. The harness filters those vector files per language via the \texttt{hybrid\_supported()} function in \texttt{tools/conformance/run.sh}:

\begin{lstlisting}[language=bash]
hybrid_supported() {
    case "$1" in
        python) return 0 ;;   # PQCK-00021, v1.2
        rust)   return 0 ;;   # PQCK-00028, v1.3
        go)     return 0 ;;   # PQCK-00029, v1.3
        c)      return 0 ;;   # TSEAL-00030, 2026-06-13
        *)      return 1 ;;   # C++ / TS / Java / CPython ext: no seal runner
    esac
}
\end{lstlisting}

The four languages without a \tesseraseal{} conformance runner (C++, TypeScript, Java, CPython ext) skip the \texttt{hybrid\_*.json} files in the harness regardless of library support. This runner axis is distinct from \emph{library} support: as of 2026-06-13, C++ (TSEAL-00031), TypeScript (TSEAL-00032), and the CPython extension (TSEAL-00034) implement suite \code{0x06} at the library level --- each verified by an in-suite test that decodes the frozen \texttt{hybrid\_*.json} vectors byte-identically --- and only Java (TSEAL-00033, backlog) still rejects \code{0x06} as \code{UNKNOWN\_SUITE}. When porting hybrid into the \emph{harness} for a new language: (i) implement hybrid in that language, (ii) update the language's conformance runner to accept 96-byte hybrid seeds (the standard runners hard-coded \texttt{len(seed) != 64}), (iii) flip the language's \texttt{hybrid\_supported()} entry, (iv) verify the language's PASS count rises by 9 (one per record across the three hybrid KAT files).

The four alpha languages each gained one invalid record since 2026-06-10 from the TSEAL-00049 \code{KEM\_CT\_LEN} pin (288 standard records), one \texttt{kyberslash\_regression.json} record, and C rose from 287 to 298 by consuming the 9 \texttt{hybrid\_*.json} records once its hybrid port landed (TSEAL-00030): 288 standard + 9 hybrid + 1 kyberslash = 298.

SKIP counts are explicit, never silent: \texttt{doc} pseudo-records and records a language cannot execute emit \texttt{SKIP} lines that the harness reconciles against each file's record count.

\subsection{How CI gates the work}

\texttt{conformance.yml} is the only automatically triggered workflow in the repository: it runs on every pull request and every push to \texttt{main} (plus manual dispatch), and branch protection on \texttt{main} requires its \texttt{cross-language} job. Within that job the blocking steps are the four-language alpha run (Python + C + Go + Rust --- the four ports with their own TesseraSeal runners) and a TesseraSeal decrypt-path timing-histogram gate (\texttt{tools/scripts/timing-histogram.py --profile ci}); the full eight-language step is informational (\texttt{continue-on-error}) until the remaining TesseraSeal ports land. The ten other workflows (per-language matrices, \texttt{tessera-seal.yml}, \texttt{latex.yml}) are manual-dispatch only, for cost control. The harness is non-flaky by design: KAT vectors are deterministic, the per-language runners do not call out to the network, and the toolchains are pinned. A red harness means one of two things:

\begin{itemize}
\item A language port produced a different byte sequence for the same input. The port is wrong; fix the port.
\item The KAT vector itself changed. Shipped vectors are frozen append-only: regeneration MAY add records or files but MUST NOT mutate existing record bytes, and a mutated record fails the freeze check. A Python-reference behavior change is a spec change, requires a release-notes entry, and all other language ports must be updated to match before the PR merges.
\end{itemize}

The harness is what makes the spec-first methodology load-bearing. Without it, ``Python is right'' is just a slogan; with it, a language port that disagrees with Python is detectable in seconds.
