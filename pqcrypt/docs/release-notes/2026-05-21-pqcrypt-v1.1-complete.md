# PQCrypt v1.1 — COMPLETE

**Date:** 2026-05-21

## Summary

PQCrypt v1.1 ships: **four additional language ports** (C++, TypeScript, Java, CPython extension), **per-language conformance runners** wired into `tools/conformance/run.sh`, the **v1.1 keyfile format** with embedded public key, the **CSPRNG rewire** of `pqid/c` to consume the shared `pqtk_csprng` primitive, and a documented evaluation of the **AEGIS-128L suite proposal** (deferred to v1.2 on dep blockers).

**7-way cross-language byte-identity** for PQCrypt envelopes: Python ↔ C ↔ C++ ↔ Go ↔ Rust ↔ TypeScript ↔ Java (+ CPython extension as an 8th surface). The full conformance harness reports **1024 PASS / 0 FAIL** across Python+C+Go+Rust × all 3 projects (pqid + pqhash + pqcrypt).

## Per-PR detail

### PQCK-00011 — C++ port

Header-only `pqcrypt.hpp` wraps the C ABI in idiomatic C++:
- `pqcrypt::PublicKey`, `pqcrypt::PrivateKey` with RAII zeroization on destruction.
- `pqcrypt::generate_keypair`, `encrypt`, `decrypt`, `peek_header`, `validate`, `validate_min_timestamp`.
- Typed exceptions: `UnknownVariant`, `UnknownSuite`, `InvalidLength`, `DecryptionError`.
- Links against `pqcrypt.o + hkdf_sha3.o + -lcrypto`; Makefile recursive-builds the C reference.

8/8 tests PASS: round-trip both suites, AD binding, variant/suite rejection (12 cases), tamper detection (6 sites), peek_header.

### PQCK-00012 — TypeScript port

`pqcrypt.ts` uses the noble libraries: `@noble/post-quantum.ml_kem1024` (re-exported as `MLKem1024`), `@noble/ciphers/aes.gcm`, `@noble/ciphers/chacha.chacha20poly1305`, `@noble/hashes/sha3.shake256/sha3_256`, `@noble/hashes/hkdf.hkdf`, `@noble/hashes/hmac.hmac`. Test suite uses Node 24's `node:test`; 14/14 PASS in 148 ms.

### PQCK-00013 — Java port

`com.pqcrypt.PQCrypt` uses Java 24+ stdlib only (no BouncyCastle):
- `javax.crypto.KEM` `"ML-KEM-1024"` (SunJCE, JEP 452).
- `javax.crypto.Cipher` `"AES/GCM/NoPadding"` and `"ChaCha20-Poly1305"`.
- `MessageDigest.getInstance("SHAKE256")` (64-byte output, truncate to 32 for our salt).
- `Mac.getInstance("HmacSHA3-256")`.

SunJCE wraps keys in PKCS#8/X.509 with a fixed 28/22-byte prefix; we extract the raw 1568/3168 bytes by skipping. KAT consumption uses the *expanded* sk form (Java's SunJCE doesn't expose seed-driven keygen via the standard API). 50/50 tests PASS.

### PQCK-00014 — CPython extension

`pqcrypt_ext` is a thin Python C extension wrapping the C reference. Build: `cd pqcrypt/cpython && python3 setup.py build_ext --inplace`. API mirrors the pure-Python module but routes through C for an order-of-magnitude speedup over `kyber-py`.

29/29 tests PASS: round-trip, AD binding, variant/suite rejection, tamper detection, peek_header, validate/validate_min_timestamp, KAT consumption from `decrypt.json` (7 records) and `ad_binding.json` (6 records).

### PQCK-00015 — Per-language conformance runners

New binaries that consume PQCrypt KAT vectors alongside the existing pqid/pqhash runner:

| File | Purpose |
|------|---------|
| `tools/conformance/c/pqcrypt_runner.c` | C runner; dispatches all 7 PQCrypt op types |
| `tools/conformance/go/pqcrypt_runner/main.go` | Go runner (separate Go module) |
| `tools/conformance/rust/src/bin/pqcrypt_runner.rs` | Rust runner (second binary in the existing crate) |

`tools/conformance/run.sh` updated with a new `pqcrypt_runner_cmd(lang)` dispatch; the main loop chooses between the existing runner (for pqid/pqhash vectors) and the new pqcrypt runner (for pqcrypt vectors) based on vector dir. `build_lang go` and `build_lang rust` updated to compile the new binaries.

Full harness now reports **256 PASS / 0 FAIL** per language × 4 languages = **1024 PASS / 0 FAIL** total.

### PQCK-00016 — v1.1 keyfile format

New header `pqck-key-v1.1` with embedded public key (1568 bytes cleartext) alongside the wrapped private key:

```
pqck-key-v1.1
<base64url(salt[16] || nonce[12] || pk[1568] || wrapped_sk[3168] || aead_tag[16])>
```

All new keys produced by `keygen` use this format. `KeyFile.parse()` reads both `pqck-key-v1` (legacy) and `pqck-key-v1.1` (new). The AEAD AAD binds to the header identifier so a v1.1 keyfile cannot be tampered into being interpreted as v1.

`cmd_pubkey` now works for v1.1 keyfiles without prompting for a passphrase — the pk is non-secret by definition.

5/5 v1.1 keyfile tests PASS: header verification, pk preservation, sk wrap+unwrap, legacy v1 read-compat, `pubkey` subcommand without passphrase, full serve-mode round-trip.

### PQCK-00017 — AEGIS-128L suite evaluation (deferred)

Surveyed cross-language AEGIS-128L availability in November 2026:

| Library | AEGIS-128L? |
|---------|-------------|
| Python `cryptography 46.x` | NOT available |
| Go stdlib + `golang.org/x/crypto 0.51` | NOT available |
| Rust `aes-gcm 0.10` / RustCrypto AEADs | available via separate `aegis` crate |
| TypeScript `@noble/ciphers` 1.x | available |
| OpenSSL 3.6.2 | NOT available (expected OpenSSL 4) |
| Java SunJCE | NOT available |
| BouncyCastle 1.78+ | available |

**Decision: defer AEGIS-128L suite `0x03` to v1.2 (post-2027)** when OpenSSL 4, `cryptography 47+`, and Go `x/crypto/aegis` land. PQCrypt v1.x ships only suites `0x01` (AES-256-GCM) and `0x02` (ChaCha20-Poly1305).

### PQCK-00018 — `pqid/c` CSPRNG rewire

`pqid/c/pqid.c` now `#include`s `common/c/random.h` and delegates `pqid_getrandom()` to `pqtk_csprng()`. The 60-line inline `getrandom → getentropy → /dev/urandom` fallback chain is removed (it was already extracted verbatim into `common/c/random.c` in PQCK-00002).

Build implications: `pqid/c/Makefile` now compiles and links `random.o`. `tools/conformance/c/Makefile` does the same for `conformance_runner`.

Behavior is bit-identical. All 13 `pqid/c` tests PASS. Full conformance harness still reports 1024/0.

`pqhash/c` does not use CSPRNG (deterministic SHAKE-256 over content); no rewire needed.

## What's next (v2 territory)

- **Hybrid suite (likely `0x06`)**: X25519 + ML-KEM-1024 + AES-256-GCM + UtC. The whitepaper §14.7 lists this as a v2 work item. Triggered by user demand and/or Module-LWE concern.
- **HQC backup suite (likely `0x07`)**: post-FIPS-203 fallback once HQC standardization finishes.
- **AEGIS-128L (`0x03`)** v1.2 work once polyglot library support lands.
- **Masked ML-KEM-1024** for high-assurance deployments (power-analysis-resistant).
