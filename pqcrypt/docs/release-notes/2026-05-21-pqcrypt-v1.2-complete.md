## Summary

PQCrypt v1.2 closes out the post-alpha hardening pass that began with v1.1.
Two visible additions, three operational improvements, one explicit
deferral:

- **Hybrid suite `0x06`** (X25519 + ML-KEM-1024 + AES-256-GCM + UtC) lands
  in the Python reference with full KAT coverage. Non-Python implementations
  reject `0x06` as `UNKNOWN_SUITE` per the harness skip-list; the other six
  ports follow in v1.3 so the polyglot KAT contract is preserved.
- **CLI binary** `pqcrypt` (`keygen`, `pubkey`, `encrypt`, `decrypt`, `info`)
  shipped in `pqcrypt/python/cli.py`. Uses the plugin protocol via subprocess
  for key custody — no private keys ever read from `argv`.
- **GitHub Actions** `pqcrypt.yml` (8-job matrix: python/c/go/rust/ts/java/
  cpython-ext/latex on Ubuntu + macOS) and updated `conformance.yml` (kyber-py
  install, OpenSSL libssl-dev, alpha-langs run then full best-effort).
- **Bench sweep**: every alpha language now has a refreshed
  `pqcrypt/benchmarks/<lang>.txt` from the M4 Max host. New Rust + C
  custom-time harnesses mirror the pqid pattern.
- **Security audit notes** (`pqcrypt/docs/security-audit-v1.2.md`)
  document the threat-model checklist, known-attack table, per-language
  posture, and 6 open items for an external auditor.
- **AEGIS-128L (suite `0x03`) deferred**: 2026-05-20 polyglot library
  survey found AEGIS unimplemented in Python/Go/Java/OpenSSL. Spec
  amendment shelved; AEGIS remains reserved-future. See PQCK-00020.

## Wire / API changes

- **Suite byte `0x06` allocated** for hybrid X25519 + ML-KEM-1024 + AES-256-GCM
  + UtC. Wire layout: `KEM_CT` field carries `ml_kem_ct (1568) || x25519_eph_pk (32)
  = 1600 B`; hybrid `pk = ml_kem_pk (1568) || x25519_pk (32) = 1600 B`; hybrid
  `sk = ml_kem_sk (3168) || x25519_sk (32) = 3200 B`.
- **Combiner**: `K_session = SHAKE-256("pqcrypt v1 hybrid combiner" ‖ ss_mlkem ‖ x_ss ‖ ml_kem_ct ‖ x_eph_pk, 32)`.
  Order is fixed; whitepaper §sec05 hybrid subsection cites X-Wing
  (draft-connolly-cfrg-xwing-kem) as the design ancestor.
- **Python keypair seed length** for hybrid: 96 bytes (64 ML-KEM seed + 32 X25519
  scalar). Non-hybrid suites unchanged at 64 bytes.
- **CLI surface** (Python only): `pqcrypt keygen|pubkey|encrypt|decrypt|info`.
  Stable for v1.x. Documented in `pqcrypt/python/README.md`.

No breaking changes to suites `0x01`, `0x02`, or the v1.1 keyfile format.

Performance read: Rust 1MB throughput trails C/Go because aes-gcm 0.10
portable backend does not enable ARMv8 AES intrinsics in this build; Go and
C use Apple Silicon AES instructions directly. Optimization deferred to
v1.3 (`aes-gcm` with `aes` feature enables ARMv8 intrinsics on aarch64,
estimated 6-8× 1MB encrypt speedup).

## Rollback

`git revert` the v1.2 merge commit. Wire format is purely additive (`0x06`
allocation), so reverting only removes the Python-side implementation and
KATs; on-disk envelopes signed by the v1.2 Python reference become
unreadable until v1.2 is re-installed. Rotate hybrid envelopes back to
suite `0x01` if a long rollback is required.
