\section{Failure Modes}
\label{sec:failure-modes}

\subsection{One error class for every authentication-class failure}

PQCrypt's \texttt{decrypt} API returns exactly one error category for every failure where the attacker could be probing for an oracle: \texttt{DecryptionError} (Python, TypeScript, Java) / \texttt{PQCRYPT\_E\_DECRYPT\_FAILED} (C ABI) / \texttt{Error::Decrypt} (Rust). The categories that map to this single error:

\begin{itemize}
\item Bad AEAD tag.
\item Bad UtC commitment tag.
\item Bad KEM ciphertext (ML-KEM implicit-reject path).
\item AD mismatch.
\item Unknown variant inside a decrypted internal blob (reserved for future suite-version embeds).
\end{itemize}

The categories that map to distinct \emph{structural} errors and may be distinguished safely:

\begin{itemize}
\item Truncated envelope or impossible length field (\texttt{INVALID\_LEN}).
\item Unknown variant byte at offset 6 (\texttt{UNKNOWN\_VARIANT}).
\item Unknown suite byte at offset 7 (\texttt{UNKNOWN\_SUITE}).
\item Output buffer too small (C ABI only: \texttt{BUF\_TOO\_SMALL}).
\end{itemize}

\subsection{Constant-time discipline}

Even on structural failure paths, the decrypt routine MUST execute the AEAD verify against a synthetic 32-byte key to keep timing flat. The reference implementation uses \texttt{HKDF\_Expand(prk\_zero, "pqcrypt v1 timing pad", 32)} where \texttt{prk\_zero} is a 32-byte all-zero buffer.

\subsection{Timing-histogram regression}

\texttt{pqcrypt/conformance/vectors/} ships a 100\,000-pair timing dataset (50\,000 good envelopes, 50\,000 ``bad'' envelopes with single-bit flips in eight different positions). The conformance runner measures decrypt-path latency for each and asserts:

\begin{itemize}
\item Median difference between good and bad timing $<$ 50\,ns (on the reference hardware: Apple M3 Max @ 4.05 GHz P-core).
\item 99th-percentile difference $<$ 500\,ns.
\end{itemize}

The runner uses \texttt{clock\_gettime(CLOCK\_MONOTONIC\_RAW)} where available; falls back to \texttt{time.perf\_counter\_ns()} (Python), \texttt{Instant::now()} (Rust), or \texttt{time.Now()} (Go).

\subsection{Implicit-reject semantics}

The FO transform in ML-KEM-1024 \citep{fips203,hofheinz2017fo} returns a pseudorandom 32-byte value on malformed ciphertext rather than raising an error. PQCrypt preserves this: a bad \code{KEM\_CT} produces an implicit-reject \texttt{ss\_mlkem}, which is then expanded into a useless $K_{\mathrm{aead}}$, which then fails AEAD tag verification, which finally produces the generic \texttt{DecryptionError}. The attacker cannot distinguish ``bad KEM CT'' from ``bad AEAD tag'' from ``bad commit tag'' from ``AD mismatch.''
