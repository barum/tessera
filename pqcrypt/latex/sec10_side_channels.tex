\section{Side Channels}
\label{sec:side-channels}

\subsection{Known attacks 2024--2026}

\begin{itemize}
\item \textbf{KyberSlash 1 \& 2} \citep{kyberslash}, Dec 2023 / Jan 2024: division-by-secret timing leak in ML-KEM \texttt{Decaps} and \texttt{poly\_compress}. Patched in pq-crystals reference and liboqs 0.10 in January 2024. PQCrypt vendors only post-patch implementations.
\item \textbf{PQShield power-analysis disclosure} \citep{pqshield2024}, Mar 2024: SPA on Cortex-M4 ML-KEM \texttt{Decaps} recovering the secret in fewer than 1000 traces. Mitigations live in \texttt{mlkem-native}'s masking branch; not used by default in v1.
\item \textbf{SPA-CCA on ML-KEM} \citep{guo2024spa}, ePrint 2024/2051: single-trace CCA on unmasked Cortex-M4. Masked implementations unaffected.
\item \textbf{CVE-2024-39427} (liboqs $<$ 0.10.1, Jul 2024): ML-KEM \texttt{Decaps} timing on certain platforms. Fixed pre-v1.
\item \textbf{CVE-2025-1432} (Bouncy Castle 1.78, Feb 2025): ML-KEM rejection-sampling bias on malformed public keys. Fixed in 1.79; v1 alpha does not yet include the Java port but the v1.1 Java port requires Bouncy Castle 1.79+.
\end{itemize}

\subsection{What v1 mitigates}

PQCrypt v1 mitigates software-timing side channels by:

\begin{itemize}
\item Vendoring constant-time ML-KEM-1024 implementations per language (\cref{sec:mlkem}).
\item Constant-time AEAD tag and commitment tag verification (\cref{sec:aead-commitment,sec:failure-modes}).
\item A single \texttt{DecryptionError} class covering every authentication-related failure.
\item Timing-histogram regression vectors in conformance (\cref{sec:failure-modes}).
\end{itemize}

\subsection{What v1 does \emph{not} mitigate}

\begin{calloutwarning}[Constant-time is not constant-power]
PQCrypt v1 does not mitigate power-analysis, electromagnetic-emanation, frequency-scaling \citep{hertzbleed,gofetch}, or prefetcher \citep{gofetch} side channels. Deployment in environments where an attacker can measure CPU power, EM, frequency, or memory-prefetcher behavior --- smart cards, embedded devices, shared multi-tenant hosts without DOIT-class mitigations \citep{intel-doit} --- requires additional countermeasures outside the library's scope.
\end{calloutwarning}

The companion document \texttt{pqcrypt/docs/side-channel-disclaimer.md} restates these limits in operator-facing language and links to recommended hardware-isolation patterns for high-assurance deployments.

\subsection{Forward path}

A future suite byte (likely \code{0x05} or beyond) could pin a masked ML-KEM-1024 implementation as mandatory for ``high-assurance'' deployments. The variant-byte allocation discipline supports this without breaking v1 envelopes (\cref{sec:appendices}).
