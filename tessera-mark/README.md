# tessera-mark — TesseraMark (variant `0x05`)

Keyed compact forensic mark: a 24–64 bit keyed permutation of a per-asset allocation index, with
a keyed check tag, server-side binding tag to the session TesseraID, and a whitened A/B segment
channel. See [SPEC.md](SPEC.md) and [RATIONALE.md](RATIONALE.md).

| Path | What |
|---|---|
| `rust/` | `tessera-mark` crate (KMAC256 on `sha3` cSHAKE, FF1 on `aes`) |
| `typescript/` | `tessera-mark` package (own Keccak/KMAC; FF1 on `node:crypto` AES) |
| `python/` | Reference prototype, vector generator and analysis |
| `conformance/vectors/` | `context`, `allocate`, `ff1`, `invalid` JSON vectors |

## Test

```sh
cargo test -p tessera-mark                       # from the repo root
(cd tessera-mark/typescript && npm ci && npm test)
(cd tessera-mark/python && python3 -m unittest test_tessera_mark)
```

KMAC256 is pinned to NIST SP 800-185 sample 6; FF1 to NIST SP 800-38G samples 7–9 (AES-256).
`ff1.json` is generated by `cargo run -p tessera-mark --example gen_ff1_vectors` and checked by
the TypeScript suite, so the two FF1 implementations cross-check each other.

## Security notes

Reference implementations: correctness first. The TypeScript Keccak and the FF1 numeral
arithmetic are not constant-time. Keys never leave the server; only codes are embedded.
